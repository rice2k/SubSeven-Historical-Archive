# SubSeven / Sub7 — Version-by-Version History, Features and File Evidence

This is the detailed release guide for the SubSeven family. It ties each version to its date, visual generation, historically confirmed feature categories, surviving package/file records, major differences from the previous generation, and research links.

> **Evidence rule:** a feature confirmed in 2.2 or Legends is **not** automatically assigned to an early 1.x release. When a precise delta is missing, this page says so instead of inventing a changelog.

## 1.0 — February 1999

**Generation:** first public 1.x release; early red-interface era.

**What is known:** SubSeven begins as a Windows controller/server remote-access family written in Delphi/Object Pascal. Later histories date the first public release to February 1999, with developer-retrospective material commonly placing the launch on 28 February.

**Feature evidence:** the complete 1.0 matrix has not yet been reconstructed from a trustworthy original README/changelog. Do not copy the much larger 2.1 feature set backward into 1.0.

**Local historical file record:**

- `ss.1.0-enc.rar` — 545,132 bytes — restricted historical release record.

**Historical website/package evidence:** the old `sub7.net` path collection contains names corresponding to `s7.1.0.zip` and `Sub7 v1.0.zip`.

**Difference from later 1.x:** this is the baseline. The archive is still searching for an original 1.0 README, complete internal file list and dated screenshots/forms.

**Reference / screenshot page:** [Malware Museum — SubSeven 1.0](https://www.malware.museum/release/subseven/10/)

---

## 1.1 — March 1999

**Generation:** early red 1.x.

Surviving feature catalogs associate this early branch with the core categories that made SubSeven recognizable: remote file handling, keylogging, password/account-data access, remote-screen control, system information, process/application controls, audio/voice-related functions and novelty/prank controls.

**What changed:** rapid feature expansion only weeks after 1.0. A precise original changelog is still needed before assigning individual menu items as “new in 1.1.”

**Historical package-path evidence:** `Sub7 v1.1.zip` appears in the old distribution-path collection.

**Reference / screenshot page:** [Malware Museum — SubSeven 1.1](https://www.malware.museum/release/subseven/11/)

---

## 1.2 — March 1999

**Generation:** early red 1.x.

**Confirmed broad categories:** File Manager, keylogging, password-recovery/credential-related controls, remote desktop/screen capture, system information, process management, voice/audio-related functions and prank/troll controls appear in surviving cataloging.

**What changed:** another fast March revision. The exact item-by-item delta from 1.1 remains incomplete.

**Historical package-path evidence:** `Sub7 v1.2.zip` survives in the old `sub7.net` URL record.

**Reference / screenshot page:** [Malware Museum — SubSeven 1.2](https://www.malware.museum/release/subseven/12/)

## 1.3 — March 1999

**Generation:** early red 1.x.

**What changed:** 1.3 is one of several very closely spaced March builds. The release itself is well established, but the archive does not yet have a sufficiently strong original changelog to claim a unique menu/feature delta beyond the continuing early feature expansion.

**Research priority:** original screenshot, README and package manifest.

**Reference / screenshot page:** [Malware Museum — SubSeven 1.3](https://www.malware.museum/release/subseven/13/)

## 1.4 — March 1999

**Generation:** final part of the early red 1.x visual era.

**Confirmed broad categories:** File Manager, keylogger, password-recovery category, **Registry Manager**, remote screen, system information, process management, voice/audio and novelty controls.

**What changed:** registry-management capability is specifically represented in surviving 1.4 feature cataloging, making 1.4 an important marker in the expansion from simple remote control into deeper Windows configuration management.

**Reference / screenshot page:** [Malware Museum — SubSeven 1.4](https://www.malware.museum/release/subseven/14/)

---

## 1.5 — April 1999

**Generation:** start of the iconic blue/purple **Fatsie** visual era.

A later developer retrospective describes 1.0–1.4 as using the early red design and places the switch to the more recognizable blue/purple Sub7/Fatsie look at **1.5**.

**What changed:** the most confidently documented difference is visual identity/UI presentation. Core file, credential, registry, remote-screen, system and process-management categories continue.

**Why it matters:** many screenshots people casually call “early SubSeven” actually belong to this later 1.x design generation rather than the original red 1.0-era interface.

**Reference / screenshot page:** [Malware Museum — SubSeven 1.5](https://www.malware.museum/release/subseven/15/)

---

## 1.6 — April 1999

**What changed:** continued incremental development. The archive currently has stronger evidence for the release/date and broad capability family than for a unique 1.5→1.6 changelog.

## 1.9 Apocalypse — August 1999

**Generation:** named experimental redesign.

A developer retrospective describes Apocalypse as a **radical redesign** whose ideas influenced the later 2.0/2.1.x direction.

**Confirmed broad categories:** file management, keylogging, password-recovery, registry management, screen capture, system information and webcam capture.

**Local historical file records:**

- `ss.1.9.Apocalypse-enc.rar` — 914,392 bytes — canonical record.
- `ss.1.9.Apocalypse-enc 2.rar` — 914,392 bytes — duplicate record.

**Historical URL record:** `s7.1.9.Apocalypse.zip`.

**What changed:** not merely a new version number; Apocalypse is a visual/structural bridge between the mature 1.x UI and 2.x generation.

**Reference / screenshot page:** [Malware Museum — SubSeven 1.9 Apocalypse](https://www.malware.museum/release/subseven/19-apocalypse/)

## 2.1 — November 1999

**Generation:** mature 2.1 controller family.

This is one of the most important versions for understanding SubSeven because a contemporary SANS/GIAC paper preserves an extensive **2.1 feature list** and explicitly cites the February 2001 `sub7files.com/about/index.shtml` page as its source.

**Confirmed capability families include:**

- File Manager;
- process/application/window management;
- system-information inventory;
- screen/desktop controls;
- keyboard and clipboard monitoring;
- password/account-data categories;
- webcam/audio monitoring;
- connection/address/network utilities;
- instant-messaging/IRC-era integration;
- chat/messages/text-to-speech;
- novelty/prank controls;
- extensive client preferences and server configuration.

See [Sub7Files About — February 2001 source study](sub7files-about-2001.md) for a non-operational breakdown.

**Local historical file record:**

- `ss.2.1.0-enc.rar` — 1,394,230 bytes.
- `ss.2.1.0-enc 2.rar` — 1,394,230 bytes — duplicate.

**What changed:** 2.1 is the mature, very broad controller generation from which GOLD/M.U.I.E/BONUS/DEFCON 8 were derived. IRC control and ICQ-era functionality are strongly associated with this generation in historical references.

**Reference / screenshot page:** [Malware Museum — SubSeven 2.1](https://www.malware.museum/release/subseven/21/)

## 2.2 — March 2001

**Generation:** redesigned modular 2.2 branch.

2.2 is the clearest major architectural break after 2.1. Contemporary March 2001 reporting describes:

- increased user-interface flexibility;
- a revamped server-customization mechanism;
- smoother Windows NT/2000 operation;
- a client that was not backward compatible with previous servers;
- expanded networking capability;
- modular/plugin-oriented design and SDK discussion.

**Confirmed package applications/files:**

| File | Historical role |
|---|---|
| `sub7.exe` | controller/client |
| `EditServer.exe` | server configuration/editor application |
| `server.exe` | remote server component |
| `sin.exe` | Static IP Notifier utility |

**Confirmed broad feature categories:** Clipboard Manager, File Manager, keylogger, Network Manager, password recovery, Registry Manager, remote desktop/screen capture, shell access, system information, voice recording, webcam capture, Process Manager and prank/troll functions. Contemporary reporting additionally discusses proxy/network-sniffing functionality and plugin modularity.

**Local historical file record:** `ss.2.2.0-enc.rar` — 2,921,188 bytes.

**Historical package-path records:** names corresponding to `s7.2.2.0.zip` and `ss22.zip` survive in old site data.

**Why 2.2 mattered:** it was not simply “2.1 with more buttons.” It attempted a deeper UI/server architecture change. Later developer retrospective material notes that the modular redesign never displaced the popularity of the established 2.1.x line, helping explain why the later Legends release returned to the 2.1.x numbering family.

**Period sources:**

- [The Register — New SubSeven Trojan unleashed, 13 Mar 2001](https://www.theregister.com/security/2001/03/13/new-subseven-trojan-unleashed/855377)
- [SANS — SubSeven 2.2: New Flavor of an Old Favorite](https://www.sans.org/white-papers/958)
- [Malware Museum — SubSeven 2.2](https://www.malware.museum/release/subseven/22/)

**Generation:** late original-era 2.1.x branch.

**Confirmed package files:**

| `server.exe` | server component |
| `editserver.exe` / `EditServer.exe` | server editor/configuration application |

**Confirmed broad feature categories:** Clipboard Manager, File Manager, keylogger, Network Manager, password recovery, Registry Manager, remote desktop/screen capture, shell access, system information, **Voice Recorder**, webcam capture, Process Manager, **Application/Window Manager** and novelty functions.

**Local historical file records:**

- `sub7legends-enc.rar` — 1,339,783 bytes.

**Historical URL record:** a `sub7legends.zip` path survives in the old `sub7crew.org` crawl.

**What changed:** Legends is treated as the final original-era Mobman release and a continuation of the familiar 2.1.x family rather than 2.2’s modular numbering. The ICQ DLL and application/window/voice categories are particularly useful package/feature markers.

**Reference / screenshots:** [Malware Museum — SubSeven 2.1.5 Legends](https://www.malware.museum/release/subseven/215-legends/)

## 2.3 — March 2010 (reported later continuation)

**Generation:** community continuation/revival, not part of the uninterrupted 1999–2003 original release line.

**Local historical file record:** `SubSeven_2.3.rar`.

**What changed:** later historical summaries describe 2.3 as a revival with newer Windows-era compatibility/features, but the archive keeps its authorship, exact provenance and complete feature delta separate from the classic Mobman chronology until stronger primary documentation is recovered.

**Research rule:** do not merge 2.3 screenshots/files into the original 2.1.5/2.2 package manifests unless version-specific evidence proves a relationship.

## SubSeven Legacy — 2021 onward

**Generation:** modern non-malicious Delphi recreation by DarkCoderSc/Sub7Crew.

The official repository explicitly distinguishes Legacy from classic Sub7 and states that malicious features are not included.

**Documented benign features:**

- 2.2.x-inspired VCL/WinAPI UX;
- modern socket/OpenSSL communication;
- multithreading/concurrency;
- File Manager;
- Process Manager;
- Remote Terminal;
- Windows Session Manager.

**Modern project/build structure includes:**

- Viewer;
- Service;
- Tray/service controller;
- Helper;
- certificate generator;
- Secure Desktop DLL project;
- shared code/resources;
- Inno Setup definitions;
- x86/x64 BASS and OpenSSL dependencies.

These modern outputs/dependencies are **not** evidence that the same files existed in classic 1999 packages.

**Official source:** [DarkCoderSc/SubSeven — SubSeven Legacy Official Source Code Repository](https://github.com/DarkCoderSc/SubSeven)

## How to read this page

The archive distinguishes:

- **confirmed feature for version**;
- **family feature not yet confirmed for that version**;
- **historical package-path record**;
- **local historical preservation filename**;
- **confirmed shipped file/application**;
- **later source/remake component**;
- **duplicate / alternate record**;
- **research gap**.

That distinction is what keeps the project useful as history instead of turning a collection of screenshots and filenames into an inaccurate universal “Sub7 feature list.”
