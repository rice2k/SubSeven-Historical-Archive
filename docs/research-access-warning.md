# Research Access & Safety Warning

This repository exists for **historical preservation, software archaeology, malware analysis, defensive cybersecurity research, and education**.

## What is directly available here

The repository can directly preserve and share research material such as:

- screenshots and interface captures;
- READMEs, FAQs, changelogs and archived website pages;
- historical URLs and Wayback references;
- filenames, package names, byte sizes and duplicate relationships;
- hashes and provenance records when available;
- version manifests and EXE/DLL inventories;
- Delphi/Object Pascal project metadata and non-operational source-analysis notes;
- sanitized code examples that illustrate programming techniques without recreating a deployable RAT;
- public research papers, conference references and source-provenance links;
- the modern non-malicious SubSeven Legacy project and its documentation.

## Classic runnable malware

Some surviving historical SubSeven packages contain executable malware or material that can be turned back into a working remote-access trojan. A warning banner does **not** make those artifacts harmless.

For that reason, this repository does not turn classic executable packages or directly buildable weaponized classic RAT source into one-click public downloads.

Instead, each known artifact is preserved through its research record: filename, version, size, duplicate/variant status, provenance, screenshots, package role, historical URLs and hashes where available.

See:

- [`../data/restricted-artifacts-manifest.csv`](../data/restricted-artifacts-manifest.csv)
- [`../data/historical-package-records.csv`](../data/historical-package-records.csv)
- [`repository-file-status.md`](repository-file-status.md)

## Public third-party research/source references

When a historically important source repository, conference page, museum, vendor analysis, or archive is already publicly available, this project may link to the **research/source page** so users can inspect provenance and context.

Examples include:

- `illwill/sub7` source-provenance project page;
- DarkCoderSc/SubSeven Legacy;
- Malware Museum release pages;
- SANS/GIAC papers;
- Wayback snapshots and capture indexes;
- BSidesCT historical material.

The archive does not convert those references into hidden payload URLs, recovery passwords, deployment instructions, or direct classic-malware download buttons.

## For researchers who already possess samples

Researchers who already lawfully possess historical samples can use this archive to compare:

- expected filenames and package names;
- byte sizes;
- published hashes;
- version labels;
- screenshots and UI identity;
- known DLL/application relationships;
- source-code provenance;
- website/download-path history;
- duplicate and alternate package records.

That allows meaningful verification and software archaeology without making the repository itself a malware distribution point.

## Suggested lab handling

If you independently work with malware samples, use an isolated research environment, snapshots, no sensitive credentials, and no connection to production networks. Follow applicable law, institutional policy, and platform rules.

## Educational intent

The presence of filenames, architecture descriptions, feature names, screenshots, source provenance and historical package metadata is intended to help researchers understand **what SubSeven was, how its software family evolved, and why it mattered historically**. It is not authorization to access systems without permission.
